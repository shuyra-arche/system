# Legacy service test migration

This is an assertion-level map from the retired Python SDK test crates to the current owners on `test/legacy-service-invariants` (based at `31cf6a6`). “Covered” means the named active assertion exercises the same stable predicate. It does not imply native execution or whole-product acceptance. “Gap” means the old assertion is not represented by an equivalent current assertion; keep the old source as historical evidence until its required native or integration evidence is deliberately replaced. Tests that depend on removed Python handles, fake Faces, session transports, or old wire layouts are marked retired where that behavior is no longer a contract.

New portable assertions in this worktree:

- `server/tests/identity/book.rs::allocation_failures_leave_authority_unchanged` checks allocation failure at IdentityBook construction, derive, bind, found, membership, and waive/unbind boundaries; after each failure, the previously committed authority remains usable.
- `api/tests/protocol.rs::loader_claim_keeps_its_wire_code_and_typed_build_identity` pins Loader Claim operation code 1, rejects every truncated frame, and round-trips the current typed `Built` record. This does not assert the retired Loader-only SDK face or old Build API.

## Migration state

This map records current evidence and gaps; it is not an acceptance report. Host tests cover deterministic state and codec assertions only. Runtime, transport, allocator interaction, and kernel effect cases remain gaps unless explicitly mapped to a native target above. No legacy package should be deleted solely because its API or SDK is retired while one of its stable safety predicates remains marked **Gap**.
