# Native Unit interpretation

System owns interpretation of pure Unit schema 2 / VNU2 records. The provider is
fixed at `aaa2b58c1ef0b40428dcc71d1321736156551109` with default features disabled.
`Unit` owns policy arrays while strings borrow the immutable boot archive. Its
fields cannot be changed after validation. Arc retention keeps storage alive;
it does not establish live authority.

`rights` matches each declared operation to the selected Kernel's named right.
It preserves kind, modifiability, distribution and checked relative page windows;
there is no old numeric-mask conversion. Identity references must fit the native
nonzero signed-register domain. Namespace paths, permits and identity grants use
the current System protocol types.

`Catalog` checks the current Kernel capsule, record/file identity, execution kind,
required Units, constructor references, supervisors and retirement provider
indices. It orders selected startup Units and rejects readiness cycles; requested
Units stay available without being started. Optional absent `after` names do not
become requirements. Old VNU1 records are rejected explicitly.

`tests/declarations` verifies these policy/record boundaries; the native entry
fixture decodes a genuine schema-2 VNI1 archive from Kernel's boot arguments.
The complete native Control application now consumes this interpreter. Its
basic production startup is verified separately from the remaining public
lifecycle and handoff semantics.

On ABI 11 the interpreter assigns Object, Pages or Whole Nest scopes explicitly.
Retired Share Open/Shut, Memo declarations, Nest Transfer and unqualified
Reservation operations fail closed. Schema-2 records do not carry live
Reservation identities: the actual provider must select and deliver that
authority at runtime. Execution kind is System declaration policy, not a Kernel
privilege-selection operation. The policy suite checks these rejection cases.
